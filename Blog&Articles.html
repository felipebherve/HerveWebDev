From Finance to Code

I spent years working in finance and accounting: bank reconciliation, accounts payable and receivable, payroll, invoicing. At my last finance job I ended up leading a full migration of the company's financial system to a new platform, on my own. That's when I realized how much I enjoyed the problem-solving side of it, and I started teaching myself HTML, CSS and JavaScript in 2023. I later completed a backend bootcamp in Python and Django, and I'm now studying Systems Analysis and Development. The finance background didn't go away — it's part of how I think about data and business rules today.

Da área financeira para o código

Passei anos trabalhando na área financeira e contábil: conciliação bancária, contas a pagar e a receber, folha de pagamento, emissão de notas. No meu último emprego na área financeira acabei liderando sozinho a migração completa do sistema financeiro da empresa para uma nova plataforma. Foi aí que percebi o quanto gostava dessa parte de resolver problemas, e comecei a estudar HTML, CSS e JavaScript por conta própria em 2023. Depois concluí um bootcamp de backend em Python e Django, e hoje curso Análise e Desenvolvimento de Sistemas. A bagagem financeira não foi embora — ela faz parte de como eu penso dados e regras de negócio hoje.

Building an API From a Written Spec

The final challenge of my backend course was TechTinga: a written business brief describing a company that manages software projects and tasks, with no starter code. I had to model the data, validate the business rules, build a REST API, import a CSV file in bulk and generate a yearly report — all from that one document. I also wrote down what's still not working (token authentication isn't wired up yet, and part of the sample CSV gets rejected by validation rules I wrote on purpose). Being upfront about what's unfinished felt more useful than hiding it. See the project on GitHub.

Construindo uma API a partir de um enunciado escrito

O desafio final do meu curso de backend foi o TechTinga: um enunciado de negócio escrito descrevendo uma empresa que gerencia projetos e tarefas de software, sem nenhum código pronto. Tive que modelar os dados, validar as regras de negócio, construir uma API REST, importar um CSV em lote e gerar um relatório anual — tudo a partir daquele único documento. Também anotei o que ainda não funciona (a autenticação por token não está ligada, e parte do CSV de exemplo é rejeitada por regras de validação que eu mesmo escrevi de propósito). Ser transparente sobre o que está em aberto pareceu mais útil do que esconder. Veja o projeto no GitHub.

How I Study: Memograms and Small Steps

I learn best by breaking things into small steps and writing my own notes as I go, instead of just watching a lesson pass by. Across my repositories you'll find dated lesson notes and "memograms" — small visual cards with a summary, an acronym, an example and "when to use" for a single concept, made right after I learn it. It's slower than just moving on to the next video, but it's how the concepts actually stick. My GitHub profile has the full map of what I've studied so far.

Como eu estudo: memogramas e passos pequenos

Aprendo melhor dividindo tudo em passos pequenos e escrevendo minhas próprias anotações ao longo do caminho, em vez de só assistir a aula passar. Pelos meus repositórios você vai encontrar anotações de aula datadas e "memogramas" — pequenos cartões visuais com um resumo, um acrônimo, um exemplo e "quando usar" para um único conceito, feitos logo depois de eu aprender. É mais lento do que simplesmente seguir para o próximo vídeo, mas é assim que o conteúdo realmente fica. Meu perfil no GitHub tem o mapa completo do que já estudei até agora.
